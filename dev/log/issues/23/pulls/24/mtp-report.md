Confirmed downstream with .NET SDK 11.0.100, Microsoft.Testing.Extensions.Telemetry 2.5.3 and latest Microsoft.ApplicationInsights 3.2.0 in https://github.com/link-foundation/php-ai-driven-development-pipeline-template/pull/24. The telemetry source still calls `TelemetryClient.TrackEvent(string, Dictionary<string,string>, Dictionary<string,double>)`; the ApplicationInsights 3.x breaking-changes guide explicitly removes that overload. Updating a consumer's central package version alone therefore cannot migrate the compiled telemetry caller.

We retain AI 2.23.0 while pinning the compatible MTP packages to 2.5.3 and other Microsoft.Extensions packages to 11.0.0. Full tests and the transitive NuGet vulnerability audit pass. A proposed upstream migration is to use the new event API for properties and record metrics separately, validating metric names against 3.x restrictions, or finish the SDK-aligned OpenTelemetry route discussed above. Please keep a test that exercises actual telemetry construction and event/metric emission, since a test run with telemetry disabled would miss this API incompatibility.
